# HTTP Server

A small HTTP/1.1 server written in plain Java. It listens on port `4221`, accepts multiple TCP clients, and supports text responses, gzip compression, and file upload/download operations.

## Requirements

- Java Development Kit (JDK) 8 or newer
- A terminal opened in this directory

Check that Java is installed:

```powershell
java -version
javac -version
```

## Project Structure

```text
HTTP_Server/
|-- Main.java       # Server entry point and request handling
|-- Main.class      # Compiled output, generated by javac
|-- README.md       # Project documentation
`-- httpServer.code-workspace
```

The application is intentionally dependency-free. It uses Java standard-library classes for networking, file access, character encoding, and gzip compression.

## How the Server Works

### 1. Startup

`Main.main`:

1. Reads the optional `--directory <path>` command-line argument.
2. Creates a `ServerSocket` on port `4221`.
3. Waits for incoming TCP connections.
4. Starts one thread for each accepted client.

Example startup command:

```powershell
java Main --directory .\files
```

If no directory is supplied, the server uses the current working directory for `/files/...` requests.

### 2. Client handling

`handleClient` performs the following steps for each client:

1. Reads the HTTP request line.
2. Parses the request method and path.
3. Reads request headers until the empty separator line.
4. Extracts `Connection`, `Accept-Encoding`, `User-Agent`, and `Content-Length` values.
5. Routes the request to the matching endpoint.
6. Writes the response headers and body.
7. Keeps the connection available for another request unless the client sends `Connection: close`.

Each response is flushed immediately. The socket is closed when the client disconnects or requests connection closure.

## Supported Routes

### `GET /`

Returns a plain-text greeting:

```text
HTTP/1.1 200 OK
Content-Type: text/plain

Hello, World!
```

### `GET /echo/<text>`

Returns the text after `/echo/`.

```powershell
curl http://localhost:4221/echo/hello
```

If the request advertises gzip support, the response is gzip-compressed and includes `Content-Encoding: gzip`:

```powershell
curl --compressed -H "Accept-Encoding: gzip" http://localhost:4221/echo/hello
```

### `GET /user-agent`

Returns the value of the request's `User-Agent` header:

```powershell
curl -A "ExampleClient/1.0" http://localhost:4221/user-agent
```

If no `User-Agent` header is supplied, the server returns `400 Bad Request`.

### `GET /files/<name>`

Reads a file from the directory passed with `--directory`.

```powershell
New-Item -ItemType Directory -Force .\files
Set-Content .\files\example.txt "hello from a file"
java Main --directory .\files
curl http://localhost:4221/files/example.txt
```

An existing file returns `200 OK` with `application/octet-stream`. A missing file returns `404 Not Found`.

### `POST /files/<name>`

Writes the request body to a file in the configured directory:

```powershell
curl -X POST --data "saved by HTTP POST" http://localhost:4221/files/upload.txt
curl http://localhost:4221/files/upload.txt
```

A successful upload returns `201 Created`.

## Running the Server

From the directory containing `Main.java`:

```powershell
javac Main.java
java Main --directory .\files
```

The server will log the directory it is serving and listen at:

```text
http://localhost:4221
```

Stop it with `Ctrl+C`.

To run without a file directory:

```powershell
javac Main.java
java Main
```

## Testing with PowerShell

With the server running in one terminal, use a second terminal:

```powershell
Invoke-WebRequest http://localhost:4221/
Invoke-WebRequest http://localhost:4221/echo/test
Invoke-WebRequest http://localhost:4221/user-agent -Headers @{ "User-Agent" = "PowerShellClient" }
```

For a connection-close request:

```powershell
curl.exe -H "Connection: close" http://localhost:4221/
```

## Important Implementation Notes

- The server handles clients concurrently using one thread per connection.
- The listening port is fixed at `4221`.
- Responses include `Content-Length` when a response body is present.
- Gzip compression is implemented only for `/echo/...` responses.
- File paths are created from the configured directory and the requested file name.
- This is an educational HTTP server, not a production web server. It does not implement TLS, authentication, request-size limits, a thread pool, MIME type detection, or full HTTP parsing.
